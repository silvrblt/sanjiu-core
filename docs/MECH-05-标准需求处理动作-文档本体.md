## 〇、需求处理标准动作（v8，2026-08-15 MECH-01 三审九方终审通过，全仓强制）

老板每次提出需求后，**任何窗口/任何会话**必须走以下流程，禁止直接开发。

### 步骤 0：立案庭路由（2026-09-03 审级组合化 v6 定稿，sanjiu-core v3.0.0 起全仓强制）

1. 任务进入先提取特征（domain/scale/type/errors_ledger_count），运行立案庭路由：
   `python3 00_global-shared/tools/eep-tools/route_task.py <任务卡.json>`（规则 = tools/court/routing_rules.yaml 唯一事实源）；
   或加载 sanjiu-court skill（说「三审九方 X」即分流）；
2. 按组合执行审计链：
   - **组合 A（一审+二审）**：一审承办 → 一审对抗 Hy3 →（分歧 M3）→ **二审对抗 DS Pro 终核（必经，简单任务封顶）**；
   - **组合 B（二审+三审）**：强制域（对外交付/资金/法律/安全/框架）/跨模块重构/历史高错误率（30 天 count≥5）→ 二审承办（doubao）起步 → 三审对抗 Qwen 终核（必经）→ 分歧 K3 终局；
   - **A_exception**：单文件 bugfix → 一审自审 + 立案庭留痕 + 二审月度抽审；
   - **C_trigger**：A 运行中一审对抗 κ<0.2 且拦截>30% 或 P0 → 升三审终核；
3. 随机抽审已废止（M3 终裁 F2）：确定性路由取代；防庸俗一致由组合内一致率监测保留；
4. 视觉/工具席不经审级（视觉三级验收 L1-L3 另行）；路由结果（combo + task_type + type_route 模型推荐）入任务卡/决策台账留痕；类型路由消费层已自动接线（route_task v1.2.3+，实施与边界见 docs/type-route/）。

### 需求分析六环节（仅在首发机执行）

1. **①需求整理**：一审承办用老板**全部原话/截图/材料**归纳需求条目
   （防摘录遗失，红线 11）；
2. **②需求扩张**：联网检索关联需求（前置/后置/伴随工作、往前想一步），
   输出扩张节 YAML 四字段 `pre_req`/`post_req`/`accompany`/`scope`（范围划定）；
   **开源盘点**：先查工作仓索引（EEP `docs/assets/open-source-list/`），没有则
   GitHub 检索，安全审计 + 许可确认后引入（npm audit 0 高危/pip audit/哈希校验/
   copyleft 审批），新库必须回流更新索引；
3. **③冲突检索**：决策台账 + 既有需求文档 + 已合/开放 PR + 白板任务池
   （其他窗口承办检查）；冲突 → 写入需求文档分歧节，随对抗审计裁决；
4. **④需求文档**：含需求来源全量原文 + R 条目 + 验收标准 A–V 映射；
5. **⑤技术实现路径**：表结构/接口/前端组件/依赖，对应技术指标
   （简洁/安全/稳健/可维护）；
6. **⑥分包方案**：四机分包/并行/缩减开发时间安排，随需求文档过审。

### 三审九方审计（三件套全量）

- 审计输入 = **初始需求全部表述 + 需求文档 + 技术路径**，从承办席开始全部进入：
  对抗审计（见全量材料，防摘录遗失）→ 分歧裁决 → 承办不服升二审 → 三审 → 抽审；
  无分歧且对抗放行 → 直接定稿（不滥用裁决）。

### 执行阶段（认领即执行）

- **承办自动路由（方案 A，2026-09-07 拍板）**：任务进入即立案（lead_route.py 一次输出 combo/task_type/type_route/承办模型）；类型路由推荐 ≠ 当前窗口模型时，承办产出由推荐模型经桥接生成（窗口会话 = 编排/验收）；manual/tool_seat/ui_design 分支按指引；非候选池 --force-model 需显式授权；
- 定稿后一审承办按技术路径**白板发包**（spec 路径写入任务卡 payload）；
- 各机器认领后**直接执行**，不再重复需求分析（需求分析仅在首发机执行）；
- **汇总机动态规则**：在线探测顺序 香港 → casensus 云 → Mac Mini → 本机，选
  第一个可用；发包机离线自动移交；含香港在内全部不可达 → 任务 pending +
  30 分钟重试探测 3 次 → 飞书告警老板人工兜底；
- 执行 → 逐条验收（截图+像素丈量+读图双证据，A–V 22 项）→ 在线机合并部署。
