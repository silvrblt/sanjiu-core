## 〇、适用范围（v1.7 项目决策人拍板 + v1.8 细化，按交付类型分闸）

| 交付类型 | 是否适用 Run-Gate |
|---|---|
| 网站/后台/小程序/H5/前端页面（开发、修改、BUG 修复、重构） | **强制**——交付前按「完整走一遍」口径走查（打开→渲染→登录→交互→数据可见→控制台零错），无运行证据一律打回 |
| 接口/后端服务/部署态交付（含 nginx 跳转链/端口/证书/防火墙） | **强制**——有 UI 载体走浏览器走查；**无 UI 载体（纯接口/CLI/守护进程）走接口级验证**（§四·五：进程 active + 探针/接口 200 + 关键动作断言 + 留痕），禁止套用浏览器工具或编造浏览器证据 |
| 混合交付（主体含页面） | 页面部分强制走查；纯文本部分不套 |
| 纯文档/报告（Word/PDF/PPT/Markdown 等所有纯文本交付） | **豁免**——不套浏览器 E2E；其中特定商业报告额外适用格式闸门 |s 报告额外适用 MECH-18 格式闸门 |
| 纯图像素材（视觉生成/UI 图） | 豁免——走视觉三级验收（L1/L2/L3） |
| 咨询/分析/需求文档等纯文本交付 | 豁免——走需求文档与审计流程 |

**仲裁判据**：以**交付物主要载体**判定——主要载体为「需运行才能使用的软件载体
（页面/接口/服务进程）」则强制（无 UI 的走接口级验证），否则豁免。豁免类型内如附带
可运行 demo，**附带可运行 demo = 交付包内或交付说明中提及的任何可运行载体（无论受众），
一律强制 R0**（≥1 个交互即算，不得借「附带/内部预览」名义逃避）；**含 JS 交互的页面化文档（HTML 交互型交付）归 08b**，不属纯文档豁免。
**发包任务同等适用（v1.9 定稿，项目决策人拍板）**：本地-服务器协同发包（AGENTS.md §十五）、
远程执行体（远程 agent/服务器/容器/第三方服务）返回的**全部工作成果**（代码/文档/
数据/配置/二进制等）视为交付——按本闸门适用范围分闸处理：代码类必须过 R0（含
R0-1~9 全部子项；纯 API/CLI 按 §四·五 接口级验证，不走浏览器 R0-1~7）+ 附运行
证据，无证据一律打回；文档/报告类走豁免路径（仍须附交付
说明与 curl 级链接抽查）；禁止以「远程产出」「非代码」名义绕过。**证据最小集（发包
场景）**：云端执行日志（带签名时间戳）+ 本地复现脚本 + 输出成果 SHA-256 哈希清单；
云端执行环境须先过 sync-local 校验（AGENTS.md §十五 既有要求）；**异常返回分级（v1.9）**：
超时/失败/格式损坏 = 无证据打回；云端日志丢失但本地复现成功 = **容器化/CI 可复现
报告优先，无 CI 环境时允许补交本地证据包后放行**（注明缺失原因）。豁免路径的 curl 级链接抽查**仅限 staging/预发或预注册
只读 URL，禁连 prod 未注册地址**（与安全死线一致）。
**本闸门为补充而非替代（v1.9，项目决策人确认）**：MECH-08b 是**三审九方流程的交付验收
补充项**——不替代需求分析六环节、不替代对抗审计、不替代裁决、不替代人工终审；
仅在「交付放行」环节追加可运行性硬门槛（R0-1~9），其余环节全部照旧。
**安全死线（v1.8；v1.10 增补）**：交付态全量交互验证**仅允许 staging/预发/隔离环境 URL**；
**禁止对生产环境 URL 直跑全量交互**（防生产脏写），违者按审计违规处理；**迁移期
等价脚本同等适用本死线**（仅隔离环境运行并留痕）。
**（v1.10 增补）执行前声明环境类型**：每轮交付态验证开始前，须在**任务卡或验收记录**
中写明本次目标环境（「隔离环境」/「生产只读」）及依据；**声明缺失即视为不合规**；
未声明而直跑生产全量交互，除按审计违规处理外，还须**记入复盘并提报错误模式**
（AGENTS §十三·16 为该要求在本文件的指向）。生产环境仅允许只读探针级验证
（**探针限定预注册 URL 列表**，防 SSRF/拖库）。**交付物密钥扫描**：交付包不得含
明文口令/令牌/密钥（docker-compose/.env 等一律走 env/secret 注入），违者打回。
**与相邻机制边界（v1.8）**：MECH-08 = 开发期每审级浏览器 E2E（责任在承办与对抗席）；
MECH-08b = **交付期最终闸门**（交付态独立重测，复用 MECH-08 证据仅作旁证——**不设
旁证减免**，防复用造假，K3 v1.2 口径「全量=每项独立重测非复用即过」不变）；
MECH-18 = 报告格式闸门（与 08b 按交付类型互斥，报告豁免 08b）；
视觉三级验收 = 纯图像素材（页面可运行性归 08b；样式视觉问题归视觉席——**可运行性
优先：交互阻塞/事件绑定失效/控制台错归 08b（含 CSS 导致的按钮不可点），纯静态样式
归视觉**，争议以可运行性为第一判据）。

## 一、验收标准（R0 可运行性）

| 项 | 断言 | 证据 |
|---|---|---|
| R0-1 可打开 | 真实浏览器访问 → HTTP 200 + title 含项目代号 且 非默认页关键字（Welcome to nginx/Index of/404 Not Found）且页面文本非空（≥50 字符） | 截图 + status + title + 文本长度 |
| R0-2 可渲染 | DOM 挂载 + 页面文本非空 + 零 pageerror | DOM 断言输出 |
| R0-3 资源完整 | 全部静态资源 200（JS/CSS/图片/favicon）——零 404（含子路径 base 校验） | 控制台/网络日志 |
| R0-4 可交互 | 登录/按钮/导航/表单真实点击输入提交 + 动作后状态断言 | 交互脚本 + 断言 |
| R0-5 数据可见 | 数据源非空（接口返回 >0 条）时页面文本含 ≥1 条数据标识——全 0 或空壳即 FAIL；**空态统一证据集（v1.9 整合）**：接口实测零数据响应（截图含 URL/计数/时间戳/trace-id/账号同帧）+ 动态空态组件断言 + 同源比对表（URL/计数/时间戳/哈希，后端日志片段与接口响应二选一，缺失任一判 FAIL）；后端非本交付物范围时以接口 200 空数组响应截图 + trace-id 替代后端日志片段（同帧绑定不变）；v1.6 无痕/隐身加载强制 | 截图 + 文本断言 + 接口计数 + 请求标识 |
| R0-6 控制台干净 | console.error/pageerror/requestfailed 零 | 控制台日志 |
| R0-7 鉴权链路 | 登录/匿名/角色切换真实走通（token 落位 + 页面状态切换） | 断言输出 |
| R0-8 后端可服务 | 服务进程 active + 探针 200 + **≥2 个核心业务接口 200 且响应字段契约断言**（v1.3：防探针过而业务挂）；前端-only 交付见 §四·五 例外（v1.9） | systemctl + curl + 字段断言 |
| R0-9 公网可达 | 部署态公网 URL 可打开（跳转链/证书/防火墙/安全组全验证）；**公网实测仅限只读探针级（R0-1 等效 + 探针 200），禁交互态直连 prod（见 §〇 安全死线）**（v1.9） | 公网实测 |

## 二、证据契约（承办交付必附，缺失 = 打回）

1. 浏览器 E2E 证据包：关键页截图 + 控制台日志（零错误）+ DOM 断言输出 + 交互动作记录；**证据元数据强制（v1.1~1.4）：ISO 时间戳 + 操作人 + 工具版本 + 环境指纹 + 证据包 SHA-256 清单（全量文件哈希——非选择性列示）；审计侧独立校验——对抗席对全部证据文件重算 SHA-256 比对 + 环境指纹核验（v1.4 防选择性规避）**；**脱敏强制（v1.8/v1.9）：Cookie/令牌掩码（Bearer 一律截断为 `Bearer ***`）、PII 截图打码，
  口令/token 只从 env/secret 读取，禁止任何明文 token 出现在日志/截图/证据包；**URL 携带凭据参数（token/key）时截图与日志须擦除该参数**（v1.9）**
2. 运行证明：进程 active + 探针 200 + 公网访问实测（staging/预发 URL，见 §〇 安全死线）
3. 审计输入必须含证据包路径（红线 11 扩展：证据全量进审计）

## 三、执行期检查清单（固化已踩坑，交付前自查）

- 子路径部署 base（Vite base=/devpanel/ 等）→ 资源零 404
- 根路径跳转（根地址不落 nginx 默认页）
- 前后端数据契约字段（嵌套 vs 扁平、null 兜底、可选链）
- 登录链路（login 排除清单、token 落位、角色切换）
- 端口冲突 / 防火墙 / 安全组 / 证书（自签说明与信任指引）
- 数据推送链路（扫描基线 → 入库 → 页面显示真实数据）

## 四、打回规则

- 任一 R0 项 FAIL 或证据缺失 → 打回，修复后重跑全量 E2E 出新证据
- 证据造假（伪造截图/日志）→ 红牌，两轮禁发
- 「代码存在即满足」彻底废除（红线 #10 执行细则升级为本闸门）
- 验收优先级：可运行性 > 需求完成度 > 代码风格（三者全过才放行）

## 四·五、例外附录（v1.1）

- 内网部署：R0-9 改为内网可达验证（公网项豁免，注明部署形态）
- 纯 API/CLI：不走浏览器 R0-1~7，改走接口级验证（进程 active + 探针/接口 200 + 关键动作断言 + 控制台等价物零错）——仍须附运行证明
- 前端-only 交付（后端非本交付物范围）：R0-8 以**接口契约断言（mock/契约测试证据
  + 依赖接口 200）**替代进程 active 检查（注明后端为外部依赖）；R0-9 公网实测按安全
  死线只读探针级
- 静态单页/文档类：R0-1~3/6 必查，R0-4/5/7 按实际交互面裁剪（裁剪须注明）
- **排他（v1.9）**：凡触发 §〇 demo 强制条款（≥1 交互即强制 R0）的交付，禁止援引
  本节任何裁剪，必须全 R0 相关项实测

## 四·五·五、性能护栏（v1.9）

- 单系统交付走查默认超时 **30 分钟/系统**，超出须在证据包声明放宽原因并记录（大型
  系统按模块分批，每批独立走查与计时）。
- 全部证据 SHA-256 统一**小写 hex** 表示（大小写混用视为证据格式不合格）。

## 五·五、对抗审计提效工具（v1.9 定稿，已装 skills 制度化接入，按交付物类型加载）

> 目的：对抗席审计代码/页面类交付时优先加载已装 skills 提效。**接入语义 = 环境可用时
> 自动推荐调用，绝不阻塞基线审计**；skill 不可用/故障不影响 R0 判定与审级流程。
> **纪律（红线级）**：skill 输出仅作审计提示，**禁止作为放行/打回唯一依据**——所有
> 裁决由审级席位独立作出；skills 不构成审级席位、不改变九方矩阵与裁决链、不单独构成
> 否决项（与视觉席同构）；grill-me 已并入一审对抗审计（机制 v6.1），不重复列为提效工具。

| 场景 | 工具 | 用途与护栏 |
|---|---|---|
| 代码类交付对抗审计（R0-8 后端/接口证据审查） | `code-review`（mattpocock，已装） | 结构化代码评审清单，审计输入侧逐项核对 |
| 大仓库审计省 token（>50 文件） | `code-review-graph`（已装，MCP） | 建调用图后 query importers_of/callers_of（实测 token 降 72.6%，基准测试 2026-08-26）；**护栏：仅用于初步筛选，必须配合 code-review 抽样复核；核心模块/高危变更禁用 graph 或执行二次全量审查** |
| R0 验收对照（需求完成度维度） | `to-spec`（已装） | 交付物 vs 需求 spec 逐条对照（与可运行性互补）；**输出仅作提示，须人工独立判定** |
| 文本/报告类校对（豁免类交付） | `impeccable`（已装） | 校对精修，与 MECH-18 格式闸门互补 |
