### 2.3 对抗审计的执行流程（怎么跑）

```
承办产出（含全部 §2.1 材料）→ 立案庭路由定组合（A/B/C_trigger）→ 审级对抗调用
  → bridge_core：SYSTEM（输出约束 + errors-ledger top5 注入 + focus）
```

**缺口识别（guard 制度化的依据）**：现行 S1-S7 全部围绕"需求满足度 + 机制合规 + 行为正确"——**代码质量维度（Clean Code/SOLID/DRY/LLM 失败模式/测试/文档完整性）没有制度化入口**：clean-code-guard 等技能存在但靠模型自觉调用（盲测实证：GLM 自发跑过，DS 未跑），无统一标准、无强制、无留痕。

## 三、guard 制度化方案（老板问 3）

### 方案（供三审九方裁决）：guard 维度并入全体对抗审计执行标准（工具层强制）

1. **维度内化（R1）**：把 guard 检查清单（clean-code-guard 的 Clean Code/SOLID/DRY/YAGNI + LLM 失败模式 + test-guard 的测试充分性 + docs-guard 的文档完整性）**固化为对抗审计的 S8 标准**——作为文本注入 bridge_core SYSTEM（同 errors-ledger 注入机制），所有审级对抗调用自动携带"代码质量检查维度"；
   - 注入文案：约 8-12 行检查项（非技能全文，控制输入膨胀 ≤500 token）；
   - 适用对象（v2）：**bridge_core 按输入材质自动判定**（材料含代码/测试/文档产物即注入 S8），纯机制/分析材料自然不触发（材质判定非自觉豁免）；**S8 注入不受 focus 范围限制，focus 仍存在且仅约束审计重点排序（不取消 focus 机制，v3 澄清）**；
2. **执行要求（R2）**：对抗席对代码类产出除 S3 需求对照外，须对 S8 逐项检查（函数长度/重复/魔法数/LLM 幻觉风险点/测试覆盖/文档与实际一致），发现即入问题清单——**无论哪个审级（一审 Hy3 / 二审 DS Pro / 三审 Qwen）一视同仁**（老板原话）；
3. **高风险全量保留（R3）**：对外交付/资金/安全域（组合 B）代码交付仍跑 guard skill 全量（clean-code-guard + test-guard）作对抗审计前置证据，结果随材料送审（不留痕的自发调用废止）；
4. **guard 触发留痕（R4）**：bridge_core 调用日志记录 guard 维度是否执行（compression 同级字段）；月度统计触发率与拦截问题数（替代 TRIGGER-RULES 埋点，09-30 兑现）；
5. **guard skill 本体的归属（R5）**：guard-skills 保持 agents-skills 仓外部技能（开源引入，MECH-MAP 已注）；机制仓不复制其代码，只引用维度清单（维度清单 = 机制仓 tools/guard-dimensions.md 单一事实源，供 bridge_core 注入读取）。

### 技术路径

- P1：`sanjiu-core/tools/guard-dimensions.md`（S8 维度清单单一事实源，起草自 guard 技能说明）
- P2：bridge_core `_build_system_prompt` 扩展——SYSTEM += guard-dimensions 注入（加载失败显式降级，同 errors-ledger）
- P3：yaml 新配置位 `guard_dimensions: {enabled: true, max_lines: 12}`（**max_lines 为待校准值，D 项实测后定**；或动态读取维度文件行数）
- P4：高风险交付 guard skill 全量执行流程入 MECH-08b 验收清单（R3）
- P5：日志字段 + 月度统计（R4）

### 验收（A-V）

- A1：guard-dimensions.md 落位 + bridge_core 注入生效（真实调用含 S8 文案）+ **max_lines 校准完成（09-30 前承办完成并留痕，写入配置——A1 前置项，校准前 max_lines 不得入正式配置）**
- A2：抽样覆盖一审/二审/三审各 ≥1 份代码类对抗报告，S8 检查项在问题清单出现 ≥1 次或明确"无代码质量问题"留痕
- A3：组合 B 高风险交付 guard 全量证据入验收包
- A4：月度触发率统计上线（09-30）
- D：全程落账；输入膨胀控制 ≤500 token/调用实测

## 六、分歧节

1. **注入位置（v2 终态）**：Hy3 裁决 = 条件注入但由 **bridge_core 按输入材质自动判定**（材料含代码产物即注入），非承办声明——确保强制且无膨胀；
2. **S8 与 S3 的关系**：S8 是 S3 的补充维度（质量）还是独立检查（可在需求满足后单列）——承办倾向：问题清单合并输出（同一份报告含需求缺口 + 质量缺口），避免两轮；
3. **维度清单颗粒度**：12 行精简 vs 全量 40+ 检查项——承办倾向精简 12 行（对抗席均为强模型，维度提示 + 判断力即可，全量清单膨胀输入且收益递减）。
