# MECH-08 交互级浏览器 E2E 强制验收闸门（定稿版，2026-08-20）

> 决策人 2026-08-20 拍板；一审对抗三轮 18 项修订；K3 终裁定稿（附两处裁决更正
> 与统一解释，见文末）。入册版本 v1.0，状态：生效。

> 缘起：C02 登录/部署反复出错（/console 前缀、Secure Cookie），页面类交付仅靠
> 截图与接口 200 验收，未做真实浏览器交互验证。项目决策人拍板固化本闸门。

## 一、适用范围（按交付类型分闸）

| 交付类型 | 验收闸门 |
|---|---|
| 网页/后台/H5/小程序（含嵌入 WebView） | **MECH-08 交互级 E2E（本闸门）** |
| 纯 API / CLI / SDK / 批处理 | MECH-07 接口级验证（契约/单测/调用链），不套浏览器 |
| 混合交付 | 页面部分走 MECH-08，接口部分走 MECH-07 |

**混合交付仲裁**：页面内发起的请求失败（如表单提交 500、接口 404）由 MECH-08
逐动作断言捕获并打灰；后端契约问题可另走 MECH-07，但不阻断 MECH-08 打灰。
**视口**：声明移动端适配的页面必须桌面（1440px）与移动（375px）双视口全量
遍历；未声明则至少桌面视口全量。

页面类交付无论成品或半成品、内部或对外，在**每一审级、每一环对抗审计**时
必须执行本闸门。

## 二、强制动作（无头浏览器，模拟真实用户）

1. **网址进入**：目标地址真实访问（本地/公网按交付声明）；
2. **鉴权进入**：登录/口令/会话真实完成，断言 Set-Cookie 落盘与鉴权跳转；
3. **全交互遍历**：页面每个可交互元素（按钮、输入框、下拉、开关、单选/复选、
   表单提交、分页、弹窗、hover 展开等）逐一真实点击/输入/提交；
4. **逐动作断言**：每个交互后校验——网络请求状态码与路径、DOM 变化、跳转
   目标、控制台零报错；
5. **证据链归档**：脚本 + 请求/响应日志 + Cookie 断言 + 最终截图，作为对抗
   审计输入材料，缺证据即退回补证。
   - **脱敏**：日志中 Cookie/令牌掩码；截图含 PII 时自动打码或仅截非数据区；
   - **跨端鉴权**：非 Cookie 体系（token/小程序登录态）按其机制断言，不限定
     Set-Cookie。
   - **口令来源**：登录口令只从 env/secret 读取，禁止硬编码进脚本/证据包。

## 三、例外规则

- 某功能开发中、交互按钮仅为提示性占位 → 交付说明必须**逐条显式声明**
  （"该按钮为占位，功能开发中"），否则视为未完成交付，对抗席直接打灰退回；
- 例外**不豁免**：网址进入、鉴权进入、已声明可实现的所有交互仍必须全量验证。
- **反造假**：对抗席对占位声明按 ≥20% 抽检（点击验证确无功能），并独立复现
  至少 3 个关键交互；A 级证据造假（脚本/日志/截图与实际不符）→ 记红牌，
  承办信用分扣减并升项目决策人裁决；两次红牌该承办席本轮禁发。
- **对抗席复现权**：对抗席享有同交付 env/secret **只读**权限以执行独立复现
  （使用 tools/e2e-browser-check.mjs 或等价脚本）；复现成本计入对抗审计预算
  独立记账，不抵承办工时。

## 四、打灰判定

对抗审计发现任一"已声明可实现"的交互无法操作、报错或跳转异常 → 打灰，
修复后由**承办重跑全量 E2E**（新证据包）再进下一审。**SLA 计时以"承办提交
新证据包"为起点**：对抗席 1 工作小时内完成该打灰项证据 100% 复核（非全量
历史）；非工作时间顺延至下一工时起点；自提交起累计满 1 工作小时未出复核
结论 → 升级二审/决策人；SLA 违约记**对抗席罚则账**（K3 终裁更正：复核责任
主体为对抗席，原"承办罚则账"为责任倒挂笔误）。

## 五、证据分级（写进各审级结论）

- **A 级**：真实浏览器 E2E 行为证据（脚本+日志+断言+截图）；
- **B 级**：接口/单测/静态截图；
- **C 级**：陈述。

凡"用户能否使用/能否登录/能否点击"类结论，**只认 A 级**；B/C 级不得支撑
该类结论（K3 终裁承诺，2026-08-20）。

## 六、工具与成本策略

`tools/e2e-browser-check.mjs`：通用无头 E2E 执行器——入参 URL、登录口令、
交互清单（选择器+动作+断言），CDP 真实点击/输入/截图，输出证据包。每个页面
交付直接复用；工具缺失/不适用时允许等价无头脚本，但必须留痕且同样输出证据包
（禁止仅截图代替）。

**等价脚本最低证据字段契约**（缺任一字段按 C 级处理）：交互选择器、动作类型、
请求 HTTP 状态码、DOM 差异 hash、控制台报错数、截图路径、执行时间。

成本策略：**承办全量遍历所有交互**（不抽样）；对抗席复核以证据包全量审查 +
独立复现抽检（≥3 个关键交互）为主，防止每一环都全量重跑导致成本失控；
审级越高抽检比例越高（三审 ≥30%）。

## 七、执行保障（闭环）

1. 重跑触发器：打灰后承办必须重跑全量 E2E 并提交新证据包，无新证据包不进
   下一审；
2. 复核 SLA：对抗席按工时制 1 工作小时内出打灰复核结论（见 §四），连续
   超时升级二审/决策人；
3. 造假追责：证据造假红黄牌（见 §三 反造假）；
4. 工具升级：`tools/e2e-browser-check.mjs` 随每次页面交付迭代补交互断言模板，
   沉淀为模块级可复用清单。
5. 争议出口：本机制执行中的循环性争议（对抗反复提新边界项）由承办整理
   证据包交 K3 终裁；终裁后禁止旧问题重开（K3 终局条款）。

## 八、K3 终裁统一解释与过渡（2026-08-20）

1. §四末句已按裁决更正（对抗席罚则账）；
2. §一"每一审级必须执行本闸门"统一解释：承办全量遍历义务发生于**首次交付
   与打灰重跑**；各审级对抗席的"执行"= 证据包全量审查 + 抽检复现（一审
   ≥3 个关键交互、三审 ≥30%），不构成逐环全量重跑；
3. 过渡：在途页面类交付自其下一审级起适用；已打灰重跑的，重跑一律按本闸门
   出 A 级证据包。
