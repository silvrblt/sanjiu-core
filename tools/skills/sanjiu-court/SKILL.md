# 三审九方立案庭（2026-09-29 三选一定稿版）

## 触发

所有建卡阈值内任务（预估产出 ≥300 字 / 需留痕 / 需审级）进入即自动立案；说「三审九方 X」= 显式快捷触发。纯工具类短问答直接会话答复，不立案不路由。

## 路由（第一步，必做——三选一判决）

1. 任务进入即写任务卡 JSON（含 title/description），运行立案庭三选一：
   ```bash
   python3 00_global-shared/tools/eep-tools/flow_gate.py --route <任务卡.json>
   ```
   输出结构化回执（receipt_id/combo/signature 等，sha256 锚定任务卡）。
2. **三选一（此后无承办路由环节）**：
   - **直答**：普通问答类 → 不调用三审九方，当前模型直接回答；
   - **模式 A（一审+二审）**：常规任务 → 转一审承办，进入一审程序；
   - **模式 B（二审+三审）**：强制域（对外交付/资金/法律/安全/框架/生产部署）、跨模块重构、历史高错误率 → 转二审承办，进入二审程序。
3. 每审级流转（修订版方案制）：
   - 承办分析需求、出方案（承办方案包）；
   - 对抗审计持全部原始指令，输出**修改版方案**（审计意见包 = 修订版全文 + 差异索引）结构化返还承办；
   - 承办逐条表态（承办响应包）：无异议（accept_all）→ 修改版即敲定方案，双方留痕落地；有异议 → 按【用户原话/承办分析/审计修改版/承办响应/需要裁决的问题】交**同一审级裁决，一次敲定**；
   - 敲定方案返还承办与审计双方，交回最初的承办方执行。
4. 上诉：承办或审计对敲定方案有异议 → 上诉**下一审级承办**（模式 A：二审；模式 B：三审），上诉包 =【问题背景+异议问题】（仅争议点，禁止全量复述）；上诉级 = 承办分析出方案 → 对抗审计反馈 → 仍异议 → 裁决 = **最终意见**。
5. 用户终判：涉及最终商业决策 → 裁决整理终判包（背景/争议/商业影响/建议选项）→ 用户最终判断 → 合入。

## 硬规则（防扯皮）

- 每级 对抗≤1轮 / 裁决≤1轮 / 上诉仅1次（flow_gate 硬计数，超限熔断转人工）；
- 审计调用必须携带合法路由回执（bridge_core 闸门，无回执退出码 19）；
- 七类材料包 schema 校验（承办方案/审计意见/承办响应/裁决输入/裁决输出/上诉/终判），不符拒绝流转；
- 承办与对抗必须异模型；审计输入 = 需求全量材料（红线11）。

## 纪律

- 视觉/工具席不经审级（视觉三级验收 L1-L3 另行）；
- 路由结果（回执+combo）入任务卡/决策台账留痕（红线12：可回溯）；
- 无分歧时禁止调用裁决模型（不滥用裁决）。
